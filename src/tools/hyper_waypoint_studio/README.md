# hyper_waypoint_studio

코스 웨이포인트를 **한 창에서** 보고, 고치고, 녹화하고, 미션을 중간부터 돌리는 GUI입니다.
예전의 `label_waypoints.py`(라벨링)와 `waypoint_record_gui.py`(녹화 조작판)를 대체합니다.

핵심은 "여러 코스를 한 캔버스에 겹쳐 놓는다"입니다. 탭이 아닙니다. 분기(branch) 코스가
생긴 뒤로는 `common_1.csv`와 `t_left.csv`/`t_right.csv`를 **같이** 봐야 이음매가 보이는데,
예전 도구는 어느 것도 코스를 두 개 이상 그리지 못했습니다.

## 실행

**여는 것은 미션 하나뿐입니다.** 코스 CSV도 배경 항공사진도 mission.yaml에 적혀 있으므로,
미션을 열면 코스 열한 개와 배경이 한꺼번에 올라옵니다. 코스를 하나씩 고르는 자리도,
배경 이미지를 따로 여는 자리도 없습니다 -- 캔버스가 편집 중인 미션과 다른 것을 보여 줄 수
있으면 라벨을 찍은 자리를 눈으로 믿을 수 없기 때문입니다.

```bash
colcon build --packages-select hyper_waypoint_studio
source install/setup.bash

# 미션 하나 (ROS 없어도 뜹니다)
ros2 run hyper_waypoint_studio waypoint_studio \
  src/planning/hyper_planner/mission/mission_track.yaml --mode edit

# 인자 없이 띄우면 빈 창입니다 -- 파일 ▸ 미션 열기(Ctrl-O)로 고르세요
ros2 run hyper_waypoint_studio waypoint_studio

# launch는 mission_track.yaml이 기본값이라 그냥 띄우면 다 차려집니다
ros2 launch hyper_waypoint_studio studio.launch.py mode:=drive
ros2 launch hyper_waypoint_studio studio.launch.py \
  mission_yaml:=$HOME/HYPER/src/planning/hyper_planner/mission/mission_school.yaml
```

미션을 바꾸면 **작업 공간이 통째로 바뀝니다** -- 열려 있던 코스는 전부 내려가고 새 미션의
코스와 배경이 올라옵니다. 이전 미션의 코스를 남겨 두면 지금 미션이 모르는 선이 캔버스에
섞이고, 라벨 스냅 거리를 그 선에 대고 재게 됩니다. 저장하지 않은 편집이 있으면 창을 닫을
때와 같은 대화상자로 먼저 묻습니다.

> **이 머신의 VSCode 통합 터미널에서는** snap이 주입하는 `GTK_PATH` 때문에 GUI가 즉시
> 죽습니다. 앞에 다음을 붙이세요:
> `env -u GTK_PATH -u GTK_EXE_PREFIX -u GDK_PIXBUF_MODULE_FILE -u GDK_PIXBUF_MODULEDIR`

**ROS는 선택입니다.** rclpy를 못 올려도(또는 `--no-ros`) 창은 그대로 뜨고 보기/편집은 전부
됩니다. 녹화/주행 모드만 꺼집니다 -- 보기/편집이 이 프로그램의 기본 용도이기 때문입니다.

### 차량 화면 고정

`C`(또는 도구모음의 **차량 화면 고정**)를 켜면 차량이 늘 화면 한가운데에 오고,
**차량 헤딩이 늘 화면 위쪽을 향하도록 뷰 자체가 함께 회전합니다**(heading-up).
녹화하면서 차가 코스를 벗어나는지 보거나, 주행 중에 한 구간을 따라갈 때 매번 팬하거나
지도가 어느 쪽을 향하는지 다시 가늠하지 않으려는 것입니다. 격자와 코스는 map 프레임에
고정돼 있으므로 뷰를 따라 같이 돌지만, 라벨/핸들/차량 삼각형은 (`ItemIgnoresTransformations`
덕에) 화면에서 늘 똑바로 보입니다. 줌은 그대로 되고, 커서가 아니라 **차량을 기준으로**
줌합니다 -- 커서 기준으로 줌하면 차가 화면 밖으로 밀렸다가 다음 pose에서 튕겨 돌아옵니다.

**가운데 버튼으로 팬하면 고정이 풀립니다.** 고정한 채로 팬을 무시하면 화면이 죽은
것처럼 보이고, 왜 안 움직이는지 알 방법이 없습니다. 풀리는 순간 뷰는 회전 없이
북쪽 위(north-up)로 되돌아가고, 도구모음 버튼도 같이 풀리므로 지금 어느 상태인지가
늘 보입니다.

차량 위치가 아직 없으면(odometry가 안 들어오면) 켜 두어도 화면은 가만히 있다가, 첫
pose가 들어오는 순간부터 따라가며 회전합니다.

## 파일 안전

이 프로그램이 지키는 약속입니다.

- **파일을 여는 것은 언제나 읽기 전용입니다.**
- **명시적인 저장 말고는 아무것도 디스크에 쓰지 않습니다.** 자동 저장도, 모드 전환 시
  저장도 없습니다. 저장은 전부 같은 디렉터리의 임시 파일 + `os.replace`라, 저장 도중에
  죽어도 반쯤 쓰인 파일이 남지 않습니다.
- 웨이포인트 CSV를 truncate하는 것은 이 스택 전체에서 **레코더의 `~/start` 하나뿐**입니다.
  그게 `auto_start:=false`가 존재하는 이유이고, 스튜디오는 코스를 잃는 두 번째 경로가
  되지 않습니다. 녹화 대상이 지금 열려 있는 코스이고 그 코스에 저장 안 한 편집이 있으면
  녹화 시작을 **거부**합니다.
- 미션 저장은 `labels:` 블록들(코스마다 하나씩)과, 바뀐 콘의 `cone: {x, y}` 부분만
  **바이트 단위로** 갈아끼웁니다. `mission_track.yaml`은 수백 줄짜리 한국어 튜닝 주석이
  본문이라, PyYAML로 다시 쓰면 그게 전부 날아갑니다. 연 뒤에 파일이 밖에서 바뀌었으면
  저장을 거부하고 다시 읽을지 묻습니다.
- **열지 않은 코스의 라벨은 저장이 건드리지 않습니다.** 좌표는 그대로 다시 쓰이고,
  `# wp #N` 주석만 빠집니다(거리를 잴 CSV가 없으므로). 갈래 하나만 열고 저장했다고
  나머지 갈래의 라벨을 잃지 않습니다.
- `다른 이름으로 저장`의 기본 위치는 실차 코스가 모여 있는 `waypoints/track/`입니다.
  원본 녹화본을 덮어쓰지 않도록 정리된 코스는 다른 파일명으로 저장하세요.
- 저장한 CSV는 첫 줄이 곧 헤더입니다. 출처 같은 `#` 주석을 앞에 붙이지 않습니다 --
  읽는 쪽(`path_loader.hpp`, 스튜디오 자신)이 전부 첫 줄을 헤더로 삼으므로, 주석이
  한 줄이라도 있으면 그게 헤더가 되어 저장한 코스가 아예 안 열립니다.

## yaw 정책 -- 후진 구간이 망가지지 않게

점을 옮기면 녹화된 `yaw`가 더 이상 맞지 않습니다. 그런데 **이웃에서 진행 방향을 다시 구해
그대로 넣으면 후진으로 녹화한 구간이 조용히 망가집니다.**

CSV의 `yaw`는 EKF가 준 실제 **차체 헤딩**이고, `path_loader.hpp`의 `waypoint_heading`은
전진/후진에 상관없이 그 값을 그대로 씁니다. 후진 주차 구간(`park_t_spot`, `park_p_spot`)
에서는 이 값이 진행 방향의 **반대**를 가리키고, 그게 맞습니다 -- RPP는 진행 방향을 포즈
방향이 아니라 carrot의 차체 x부호로 판단하고, goal checker의 yaw 비교는 차체 헤딩
기준이기 때문입니다.

그래서 스튜디오는 점마다 **전진/후진 표시를 로드 시점에 한 번 정해 두고 편집으로는 바꾸지
않습니다.** 점을 옮기면 진행 방향만 다시 구하고 그 표시를 다시 씌웁니다.

판정식은 `path_loader.hpp`의 `reverse_fraction`과 같은 것(`cos(yaw)·dx + sin(yaw)·dy`)을
씁니다 -- 편집기와 로더가 같은 답을 내야 하기 때문입니다. 헤딩이 진행 방향과 거의 직각이라
한 점만으로 애매하면 ±10점 창의 다수결을 봅니다. 자동 판정이 틀린 이음매를 위해 편집
패널에 **전진/후진 뒤집기** 버튼이 있습니다.

편집한 자리가 미션의 `reverse:` 스텝 구간 안이면, 로드 시점에 `mission_loader`가 하는
것과 같은 검사를 **저장하기 전에** 돌려 후진 비율을 보여 줍니다.

## 라벨은 코스마다 독립입니다

`mission_loader`에서 라벨 이름은 **코스마다 따로**입니다. 최상위 `labels:`는 `main`
코스의 것이고, 나머지 코스는 `courses.<이름>.labels`를 씁니다. 같은 이름이
두 코스에 있어도 되고(`t_left_end` / `t_right_end`처럼 짝을 이루는 라벨), 한 코스에만
있어도 됩니다.

`main`은 선택입니다 -- `mission_track.yaml`처럼 코스가 전부 조각인 미션에는 없고, 그때는
최상위 `labels:`도 없습니다. 그런 미션에서는 코스 목록에 `main` 항목이 나오지 않습니다.

스튜디오도 그대로 따라갑니다.

- 라벨 목록은 **코스별로 묶여** 나옵니다(`— start_left —` 같은 머리줄).
- 캔버스의 라벨 글자는 `main`이 아닐 때 `이름 [코스]`로 나옵니다.
- 라벨을 배치/이동하면 **그 라벨이 속한 코스**에 스냅합니다. 지금 편집 중인 코스가
  아닙니다 -- 갈래 라벨을 고른 채 main을 클릭했다고 라벨이 main으로 옮겨 붙으면
  `mission_loader`가 그 라벨을 엉뚱한 CSV에서 찾게 됩니다.
- 그래서 어떤 라벨을 옮기려면 **그 코스의 CSV가 열려 있어야** 합니다. 안 열려 있으면
  배치를 거부하고 어느 CSV를 열어야 하는지 알려 줍니다(보통은 화면에서 뺀 코스입니다 --
  미션을 다시 열면 돌아옵니다).
- 코스와 미션 코스의 짝은 **짐작하지 않습니다.** 코스가 전부 미션의 `courses:`에서 오므로
  어느 이름인지 처음부터 알고 올립니다. 레이어 목록의 `미션 코스` 칸은 그래도 손으로
  바꿀 수 있게 남겨 두었습니다(같은 CSV를 다른 코스로 대 보고 싶을 때).

### `last` 라벨

`park_p_entry: last`처럼 좌표 대신 `last`로 적힌 라벨은 "그 코스의 마지막 웨이포인트"라는
뜻입니다. 좌표가 없으므로 캔버스에 찍히지도, 옮겨지지도 않습니다 -- 목록에 `(last)`로
회색으로 나오고 고를 수 없습니다. **저장할 때는 그대로 다시 쓰입니다.** (예전에는 좌표가
없다는 이유로 저장에서 통째로 빠졌고, 그러면 그 다음 미션 로드가 실패했습니다.)

## 라벨 스냅 -- 저장하기 전에 알기

`mission_loader`는 로드 시점에 라벨을 최근접 웨이포인트로 스냅하고, 거리가
`label_snap_tolerance_m`(보통 1.0 m)를 넘으면 **미션 전체를 거부**합니다. 점을 옮기다
보면 그 선을 조용히 넘길 수 있습니다.

그래서 라벨 목록은 스냅 거리를 실시간으로 보여 주고 색으로 칠합니다: 초록 `< 0.5×tol`,
주황 `< tol`, 빨강 `>= tol`. 빨간 라벨이 있는 채로 미션을 저장하려 하면 그 라벨과 거리를
나열하고 정말 저장할지 묻습니다.

거리는 **그 라벨이 속한 코스**에 대고 재야만 의미가 있으므로, 코스 목록의 `미션 코스` 칸에서
어느 코스가 미션의 `main` / `t_left` / `t_right`인지 묶습니다(파일 이름으로 자동 추정).
묶이지 않은 코스에는 거리를 표시하지 않습니다 -- 엉뚱한 코스에 대고 잰 거리는 없는 것보다
나쁩니다.

## 콘 마커 -- 분기 판정 좌표

`t_left`/`t_right`, `p_up`/`p_down` 같은 주차 갈래는 분기 스텝(`select_by: clearance`)의
`cases[].cone: {x, y}`에 콘 좌표를 하나씩 들고 있습니다. `mission_manager_node`가 이
좌표 주변의 코스트맵 lethal 셀 수를 세어 어느 칸이 막혔는지 판정합니다(`count_cone_cells`).
이 좌표는 **라벨이 아닙니다**:

- `courses.<이름>.labels`가 아니라 `steps[].cases[].cone`(또는
  `routes.<이름>[].cases[].cone`)에 있습니다.
- **스냅되지 않습니다.** `label_snap_tolerance_m`도, 어떤 코스의 CSV도 확인하지 않습니다 --
  콘은 녹화된 경로 옆(주차 칸 입구)에 있는 게 정상이고, 실제로 `p_up`/`p_down`의 콘은 자기
  갈래 경로에서 2 m 넘게 떨어져 있습니다. 라벨처럼 취급해 스냅했다면 그 두 콘은 허용
  오차를 넘겨 미션 전체가 로드되지 않았을 것입니다.
- 좌표 자체가 런타임 판정 지점이므로, 스튜디오가 옮기는 위치를 클릭/드래그한 그대로
  받습니다 -- 근처 웨이포인트로 끌어당기지 않습니다.

"미션 콘" 목록은 "미션 라벨"과 나란히 있지만 스냅 상태가 없어 색으로 거리를 나타내지
않습니다. 콘을 고른 뒤 캔버스를 클릭하거나 마커를 끌면 그 좌표 그대로 옮겨지고, **미션
저장**을 누르면 라벨과 같은 원자적 저장 한 번에 그 케이스의 `cone: {x, y}` 부분만
바이트 단위로 갈아끼웁니다(`value`/`goto`/주석은 그대로). 기존 콘의 위치만 옮길 수 있고,
분기 케이스를 새로 추가하거나 지우는 것은 여기서 지원하지 않습니다 -- YAML을 손으로
고치세요.

## 배경 이미지 -- 미션이 정합니다

**이미지를 고르는 자리는 없습니다.** 어떤 그림을 깔지는 mission.yaml의 최상위
`background:` 한 줄이 정하고, 미션을 열 때 코스와 같이 올라옵니다.

```yaml
# mission_track.yaml
background: real_course.png      # mission_school.yaml은 school.png
```

파일 이름만 적으면 (1) 그 yaml의 폴더, (2) `~/HYPER`, (3) `hyper_gazebo`의 `meshes/` 순으로
찾습니다. 절대 경로도 됩니다. `mission_manager`는 이 키를 읽지 않습니다 -- 로더가 모르는
최상위 키는 그냥 지나칩니다.

배치는 **`<이미지>.align.yaml` 사이드카**에 있습니다: 이미지 중심의 map 좌표, **이미지
가로 폭(m)**, 반시계 회전각(도). 항공사진에는 지오레퍼런스가 전혀 없어서 손으로 맞춘
값입니다. 축척을 픽셀당 미터가 아니라 가로 폭으로 저장하는 이유는 배경이 다운샘플되기
때문입니다 -- 픽셀 기준이면 다운샘플 배율만 바뀌어도 배경이 조용히 어긋납니다.
사이드카가 아직 없으면 올라와 있는 코스의 bbox에서 자리를 추정합니다(그래서 배경은 늘
코스보다 **나중에** 올립니다).

정렬 패널에서 옮기고/키우고/돌린 뒤 **정렬 저장**을 눌러야 사이드카에 남습니다.
`없애기`는 배경만 내립니다 -- 미션을 다시 열면 돌아옵니다.

> 예전에 있던 **시뮬 코스** 버튼은 없습니다. 그 버튼이 열던 `course.png`는 더 이상 없고
> (지금 `ground.mtl`이 쓰는 바닥 텍스처가 `real_course.png` 자신입니다), 텍스처를 쿼드
> 종횡비로 늘려 주던 보정도 필요 없어졌습니다 -- `real_course.png`는 1039×864(0.831569)로
> `ground.obj` 쿼드 121.2454×100.8238 m(0.831568)와 여섯 자리까지 같습니다.

## 로컬 코스트맵

`보기 ▸ 로컬 코스트맵`(기본 켜짐)이 nav2 컨트롤러가 실제로 보는
`/local_costmap/costmap`을 캔버스에 깔아 줍니다. 배색은 RViz의 Map 디스플레이 costmap
배색을 그대로 옮겼으므로 `follow_path.rviz`와 나란히 놓고 봐도 같은 그림입니다.

| 값 | 색 | 뜻 |
| --- | --- | --- |
| 0 / -1 | 투명 | 비어 있음 / 모름 |
| 1-98 | 파랑 → 빨강 | inflation 기울기 |
| 78-79 | 주황빛 빨강 | `drivable_area_layer`의 200 (차선 밖/오는 차선) |
| 99 | 하늘 | inscribed (253) |
| 100 | 자홍 | lethal (254) -- 라이다 장애물 |

불투명도는 **배경** 독의 `코스트맵` 슬라이더입니다(배경 이미지가 없어도 씁니다).

알아 둘 것 세 가지.

- **`controller_server`가 active여야 나옵니다.** 안 보이면
  `ros2 lifecycle get /controller_server`부터 보세요. 2 Hz로 계속 오는 토픽이라,
  3초 넘게 끊기면 레이어를 감춥니다 -- 옛날 위치에 얼어붙은 격자는 없느니만 못합니다.
- **놓는 자리는 TF가 정합니다.** 코스트맵의 `global_frame`은 `odom`(rolling window라
  origin이 매 주기 움직입니다)인데 씬은 map 프레임입니다. 그래서 매 장 `map <- odom`을
  찾아 origin을 옮깁니다. 그 변환이 없으면(전역 EKF가 안 떠 있으면) 그리지 않고 상태줄에
  이유를 씁니다. 단위행렬로 치면 EKF 전역 보정만큼 어긋난 그림이 그럴듯하게 나오기
  때문입니다.
- **`always_send_full_costmap: true`에 기댑니다**(`nav2_controller.yaml`). 매번 전체
  격자가 오므로 `/local_costmap/costmap_updates`는 구독하지 않습니다. 그 파라미터를 끄면
  첫 장 이후로 화면이 멈춥니다.

## 주행 모드 -- 미션을 중간부터

미션 후반의 스텝 하나를 고치고 확인하려고 코스를 처음부터 돌 이유가 없습니다.

스텝을 고르고 **여기서 시작**을 누르면 `set_parameters(step_index, step_label)` →
`~/goto_step` → `~/start` 순서로 부릅니다. **먼저 순간이동**을 켜면 그 앞에
`/teleport_service`도 부릅니다(시뮬 전용).

스텝 목록은 노드가 내보내는 `/mission_manager/steps`(latched)를 우선 씁니다. yaml만 봐서는
갈래(route) 스텝의 인덱스를 알 수 없기 때문입니다 -- `mission_loader`가 `routes`의 스텝을
`steps` 뒤에 덧붙이므로, 그 인덱스는 노드만 압니다. 노드가 안 떠 있으면 yaml 순서로
떨어지고, 그때 갈래 스텝은 보이지 않습니다.

**주의**: `drive` 스텝의 시작 인덱스는 로드 시점에 정해집니다. n번 스텝으로 뛰면 경로는
n-1번이 끝난 자리에서 시작하므로, 차가 거기 없으면 먼저 그리로 갑니다. 시뮬에서는 순간이동을
같이 쓰고, 실차에서는 차를 그 지점에 가져다 놓고 누르세요.

## 모듈

| 파일 | 하는 일 |
| --- | --- |
| `main.py` | 진입점, ROS 없을 때의 대체 경로, 신호 처리 |
| `app_window.py` | 창 본체 -- 모드, 레이어, 저장 규칙 |
| `scene.py` | 캔버스(map 프레임 미터, y-up), 격자, 줌/팬, 차량 화면 고정 |
| `items.py` | 배경/코스/핸들/라벨/콘/차량 그래픽 아이템 |
| `formats.py` | 파일 입출력만 (Qt·ROS 없음) -- CSV, mission.yaml의 라벨·콘 스플라이스, 정렬 사이드카 |
| `geometry.py` | 순수 계산만 -- yaw 정책, 전진/후진 판정, 스냅 |
| `course_model.py` | 코스 한 개의 편집 상태와 실행 취소 |
| `mission_model.py` | 열린 mission.yaml, 라벨/콘 상태, 스냅 보고 |
| `ros_link.py` | rclpy 노드 하나 + executor 스레드, Qt 시그널 경계 |
| `panels/` | 코스 / 배경 / 편집 / 녹화 / 주행 조작판 |

`formats.py`와 `geometry.py`는 Qt도 ROS도 import하지 않습니다. 보기/편집이 ROS 없이 돌아야
하고, 저장 안전성과 yaw 정책을 GUI 없이 `python3`로 그냥 시험해 볼 수 있어야 하기
때문입니다.
